# Music dashboard

The dashboard is served by the Rust binary at `/music/dashboard`; there is no public marketing page in this release. English is the default throughout. Its controls configure the same per-server skip policy as `/skip-settings` and clear current votes on save.

Only servers with Music installed and where the signed-in member can manage the server are listed. Reads and writes additionally verify current membership and server permissions through Discord's bot API. Moderation permission alone does not grant dashboard access.

The dedicated application's confidential OAuth code flow requests only `identify guilds`. OAuth state is browser-bound, single-use and expires after 10 minutes. Music access tokens remain in server memory; the browser receives an opaque HttpOnly, Secure, SameSite=Lax cookie scoped to `/music`. Sessions last at most one hour and are lost on restart. Writes and logout require both the exact configured Origin and a session CSRF token. Logout invalidates the local session and attempts Discord token revocation for tokens issued to Music. Music does not store tokens in browser localStorage or return them in API responses; the existing Vozen account has its own browser storage policy.

When opening Music from the Vozen account page, the site can exchange its existing ecosystem access token for a Music session using a credentialed POST from `https://vozen.org`. Music checks the token with Discord, accepts only the configured ecosystem application with `identify` and `guilds` scopes, verifies the same user identity, and limits its session to the token's remaining lifetime or one hour, whichever is shorter. Server access is still checked against current Discord membership and Manage Server permission. The account token is sent in the POST body, never in a URL. Music does not revoke an ecosystem token when signing out of Music; signing out of the Vozen account clears the Music cookie as well. Exchange failures leave the user on the account page with an error, while users without a Vozen session can still use Music's own Discord sign-in.

The HTTP server uses a body limit of 8 KiB, a global budget of 600 requests/minute, at most 200 pending authorizations and 1000 active web sessions, and 12-second outbound timeouts. These are capacity bounds, not per-user quotas. Roles are transmitted as decimal strings to retain Discord ID precision. API failures leave the form editable for retry. Current settings are saved as full form values; concurrent administrators should reload before making further changes.

Colors and avatar follow the accepted Music identity in `assets/brand/README.md`. The locally hosted Outfit Latin font is reused from the Vozen website; its license is retained in `OFL-Outfit.txt`, sourced from https://github.com/google/fonts/tree/main/ofl/outfit . No external font or analytics requests are made.

The header markup and `global-nav-v1.css` are taken from the Vozen website account navigation. Keep the stylesheet identical to `Vozen-Team/vozen-org:site/css/global-nav-v1.css` when updating the header. Its Outfit and header-display fonts are served locally at the stylesheet’s original relative paths. The profile uses the Discord avatar and separate decoration asset; the menu links return to the Vozen account and localized website.
